2. Comparison: GLON-WASM-ABI.md vs GLON-HOST-ABI.md

2.1 Agreements

  • Both mark the WASM ABI current/provisional, with no version constant or compatibility guarantee; both point to standalone/glon.c as source of truth.
  • Same module variants: W2 standalone, G1A shop, GLON_LIVE.
  • Same common exports: glon_alloc, glon_init, glon_load, glon_call, glon_run, glon_result_ptr, glon_result_len, memory.
  • Same host imports: host_print, host_set_text, host_set_html, host_canvas_script, and GLON_LIVE host_call.
  • Same G1A exports: glon_route, glon_event, glon_event_value; GLON_LIVE adds glon_event_bytes.
  • Same execution-entry lifetime rule: glon_alloc pointers are valid only until the next glon_load/glon_call/glon_route/glon_event/ glon_event_value/glon_event_bytes/glon_run.
  • Same arena model: separate 64 KiB transient abi_heap, 8-byte alignment, len + 1 reserved, reset at each execution entry.
  • Same source/token/value limits: source < 16 KiB; glon_call name <= 60; route/event token <= 63; glon_event_value value <= 200; glon_event_bytes data <= 12000; rendered HTML 16 KiB; canvas 2560 bytes.
  • Same result lifetime: glon_run result buffer is static, replaced by the next glon_run; route/event output goes through imports, not the result buffer.
  • Same singleton/re-entrancy rule: one global machine, serialised calls, no re-entry from host callbacks.
  • Same tested-host list and same ./check-frozen-s1.sh role.

3. EBNF production verification

The reader is r0_s1_runtime.c: parse_int/parse_word at 177–216, parse_string_literal at 643–661, parse_masm at 686–760, parse_block at 764–886, parse_form at 887–893, parse_program at 3963–4002.

EBNF production Implementation check Result
source = ws* ( block trailing-tail | top-item ( ws* top-item )* ws* ) parse_program: skip ws; if [ parse one block and return (trailing ignored); otherwise loop top-items to end. Matches. Corrected the earlier grammar (it wrongly made form carry string/func/masm and required whitespace between forms).
trailing-tail = any-byte* parse_program returns immediately after parse_block; no trailing check. Matches ([1] 2 parses as [1]).
top-item = string | masm-form | form parse_program handles a leading " as string, exact masm/raw via parse_masm, otherwise parse_form. It does not special-case func. Matches; top-level func is a WORD.

block-item = string | func-form | masm-form | form parse_block string branch at 776–782; func branch at 783–858; masm branch at 859–870; else parse_form. Matches.

Matches, with the note that this is block-only and body may be computed.

3.1 Corrections made during this pass

The EBNF in both the specification and syntax-diagram documents was corrected to the verified version above:

  • separated top-item (no func) from block-item (includes func);
  • separated item recognition from parse_form's form;
  • allowed zero-width separators where delimiters make the boundary unambiguous;
  • made func's body block optional (computed body left in the stream);
  • restricted masm arity to unsigned digits;
  • made token length open-ended with a 63-byte truncation note;
  • noted string item-start restriction, expansion and 512-byte limit;
  • noted the leading-block trailing-tail behaviour;
  • completed the terminal alphabets (digit, any-byte, token-byte, non-quote-byte) and quoted the whitespace terminals so the grammar is machine-readable.

These are documentation corrections, not language changes.

5. Vocabulary provenance verification

GLON-LANGUAGE-SPEC.md §4.0 now classifies every documented vocabulary group:

  • R0 natives over S1 HOST: arithmetic, comparison, print.
  • R0 evaluator mechanics: values, either, do, invoke, reduce, SIN! words, func, return.
  • Reader trapdoor: masm/raw.
  • Glon libraries: prelude/common, case, parse, strings, tasks.
  • Host imports/exports and dispatch convention: host_*, glon_*, current-*.

GLON-HOST-ABI.md §1 independently repeats the portable-vs-host split. No vocabulary entry now stands unclassified.

One nuance to preserve: arithmetic and comparisons are ordinary Glon native words even though their implementation calls frozen S1 HOST operations. They are not S1 primitives and are not library code.

  2. GLON-LANGUAGE-SPEC.md — complete descriptive surface and vocabulary.
  3. GLON-SYNTAX-DIAGRAMS.md — verified lexical grammar.
  4. GLON-EVALUATION-MODEL.md — execution, binding, result sets, errors.
  5. GLON-HOST-ABI.md + GLON-WASM-ABI.md — host boundary.
  6. GLON-ARCHITECTURE-MEMORY.md — decisions and limits.
  7. The named conformance tests for the behaviour being implemented.

The C source is needed only for unresolved details such as masm mnemonics, exact GC layout or host-specific pointer formats. It is not needed for ordinary Glon programs.

7. Remaining ambiguity and missing conformance tests

7.1 Ambiguity / unresolved behaviour

  1. Non-integer arithmetic and print. Contract says integers; runtime computes on payload / 16 without a type check.
  2. Division/modulo by zero. C undefined behaviour versus WASM trap; no contract.
  3. Non-block do/either. Used as a block address; may read unrelated memory or return nonsense.
  4. Missing/extra call arguments. Missing args read past the block; extra args remain for the following expression.
  5. func spec shape. A non-block spec, duplicate parameters, or more than 16 parameters are not validated before use.
  6. return with no expression / at end of block. The reader consumes the next form, which may be past the end.
  7. values exactly-one-result rule. Implementation fail-stops on zero or multiple results per form; laws/primer do not state it.
  8. Result-set collapse. Arguments and reduce keep the first of several results; undocumented.
  9. String literal library dependency. "..." expands to mk-string [...]; a bare core runtime halts.
  10. Host comment stripping. ;; is not parser syntax and is stripped even inside strings.
  11. Token truncation at 63 bytes and silent symbol collision.
  12. Leading block ignores trailing source forms.
  13. reduce rejects managed source blocks.
  14. none literal versus none:/'none.
  15. masm empty-block validation fails after parsing, not as a lexical rule.

7.2 Missing conformance tests (prioritised)

  1. Argument collapse: + values [1 2] 3, print values [1 2], reduce [values [1 2] 3].
  2. values zero/multi-result forms and nested values.
  3. Non-block do/either, and missing/extra function arguments.
  4. func non-block spec, duplicate parameters, 17+ parameters.
  5. return outside a function and return at end of block.
  6. String with ;; inside, unterminated string, backslash/quote handling.
  7. 64+ byte token and two tokens sharing a 63-byte prefix.
  8. none: 5 none and 'none equality/molding.
  9. reduce reduce [1] (managed source).
  10. Non-integer operands for each arithmetic/comparison word.
  11. Division and modulo by zero on native and WASM.
  12. Source starting with a block followed by more forms.
  13. print of NONE, word, block, string and closure.
  14. func at unwrapped top level versus inside a block (site/scope).
  15. func "x" [1] inside a block (spec is a word, not a string).
  16. masm[ ], masm 1[], masm1[], and masm -1 [] lexical cases.
  17. Form adjacency: a[1], 1"x", a"b".
  18. Host comment stripping through each host path (native session, WASM glon_load, glon_run, CLI).

The current suite already covers the main language laws, closures, case, parse, strings, SIN!, escape law, memory/GC, tasks and primitive models; these gaps are concentrated at lexical boundaries, result-set collapse and unchecked non-block/argument cases.
